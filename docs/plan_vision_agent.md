# 下一階段規劃：視覺引導取放 + 自然語言操作（TM5S）

2026-11-26 擬定。經理尚未指定下一步，先自行決定方向；經理回覆後依他的意見調整。

## 1. 目標

把已經完成的四個部分串成一個完整的應用：

> 使用者用中文說「把杯子放到右邊」→ 本機 AI Agent 理解指令 → 相機 + YOLO 找到杯子的位置 → TM5S 自己去夾取並放到指定區域 → Agent 用實際量測結果回報。

| 用到的現有成果 | 在這個應用裡的角色 |
|---|---|
| 階段 1：本機 Ollama Agent（工具呼叫、程式層規則、審查） | 理解中文指令、決定呼叫哪個工具、回報結果 |
| 階段 2：YOLO v3（Gazebo 自訂資料訓練，杯子／瓶子／人） | 從相機影像找出物體 |
| 階段 3：TM5S + MoveIt 2 取放 | 實際夾取與放置 |
| 自走車專案的驗收方法（用 Gazebo 真實位置核對） | 驗證定位誤差與取放結果 |

**為什麼選這個方向：** 視覺引導取放是工廠自動化最常見的需求（物體位置不固定，要靠相機找）。加上自然語言操作，可以展示四個階段整合後的完整系統。全部在現有的 Gazebo + MoveIt 2 上完成，不需要另外安裝軟體。

**不在範圍內：** 實體機器人、Isaac Sim、深度相機（先用單一彩色相機 + 已知桌面高度）、物體姿態估計（杯子把手方向固定）。

## 2. 系統架構

```
Gazebo（TM5S + 桌子 + 固定相機 + 杯子 + 瓶子）
   │ 影像 /table_camera/image（ros_gz_image 橋接）
   ▼
detect_objects：YOLO v3 偵測 → 像素轉桌面座標（相機內參 + 已知相機位置 + 射線與平面交點）
   │ [{類別, 信心值, 世界座標 x, y}]
   ▼
pick_place_demo.py（擴充成可夾圓柱物體）→ MoveIt 2 → TM5S + 夾爪
   │
   ▼
驗證：Gazebo 真實位置（物體有沒有到目標區域、誤差多少）

AI Agent（Ollama Llama 3.1 8B）
   工具：list_objects（看桌上有什麼）、pick_and_place（把某物放到某區域）、scene_status（查目前位置）
   程式層規則：只能操作偵測到的物體、只能放到定義好的區域、數字只能來自工具結果
```

## 3. 工作項目

### A. 場景（約 1 小時）

- 用程式產生 `vision_world.sdf`：在現有 TM5S 場景加上
  - 固定相機：放在桌子遠端（+x 側），高 1.45 m，往下約 36° 看工作區，640×480，視角 0.9 rad。放在手臂對面，避免手臂擋住視線。
  - 杯子和瓶子：用 YOLO 訓練時同樣的基本形狀產生（訓練資料就是這些形狀），加上碰撞體和質量，才能被夾起來。兩個都是直徑 9 cm（夾爪張開 12.2 cm），杯子把手固定朝 ±x，不會卡到手指。
  - 原本的方塊移到工作區外。
- 驗收：相機影像正常輸出；YOLO 在這個角度能偵測到杯子和瓶子（信心值 ≥ 0.5）。

### B. 定位：像素 → 桌面座標（約 1.5 小時）

- 由視角和影像大小算出相機內參；相機位置和角度已知（固定在世界裡）。
- 偵測框中心 → 射線 → 和「物體中間高度的水平面」求交點（杯子 5 cm、瓶子 8 cm，依類別已知）→ 得到物體中心的 x, y。
- 驗證：隨機擺放 20 次，和 Gazebo 的真實位置比較。
- 驗收：平均定位誤差 ≤ 1.5 cm，最大 ≤ 3 cm（夾爪兩側各有約 1.6 cm 餘量）。

### C. 視覺引導取放（約 2 小時）

- 擴充 `pick_place_demo.py`：
  - 支援圓柱物體（MoveIt 碰撞物體用圓柱，依類別給半徑與高度）；
  - 夾取寬度依物體半徑計算（接觸點 + 5 mm 夾緊，和方塊相同的做法）；
  - 另一個物體也加入碰撞場景，避免手臂撞到。
- `vision_pick_trials.py`：每次隨機擺放兩個物體 → 偵測 → 定位 → 夾取指定物體 → 放到目標區域 → 用 Gazebo 真實位置判斷成功與否。
- 驗收：**隨機擺放 10 次，至少成功 8 次**；記錄每次的定位誤差、放置誤差與失敗原因。

### D. 自然語言操作（約 2.5 小時）

- 沿用 `ai-agent/` 的 Agent 迴圈與模型介面，新增三個工具：
  - `list_objects`：回傳偵測到的物體與位置；
  - `pick_and_place(object, area)`：區域用名稱（左邊、右邊、中間、靠近機器人），由程式對應到座標；
  - `scene_status`：回傳物體目前的真實位置。
- 程式層規則（沿用階段 1 的做法）：只能操作偵測到的物體、區域必須在清單內、一次只動一個物體、回報的數字必須來自工具結果。
- 驗收：8 句中文指令全部正確，包含：
  - 一般指令：「把杯子放到右邊」「瓶子移到中間」；
  - 兩步驟：「先把瓶子放左邊，再把杯子放右邊」；
  - 查詢：「桌上有什麼」；
  - 做不到的：「把香蕉拿起來」（桌上沒有，應回答找不到，不能假裝完成）、「把杯子放到桌子外面」（區域不存在，應拒絕）。
  - 不能編造結果，也不能執行沒被要求的動作。

### E. 展示與文件（約 1 小時）

- GUI 展示腳本：Gazebo + RViz + 相機偵測畫面（含框和估計位置）+ 終端機的 Agent 對話。
- 圖表：偵測畫面截圖、定位誤差分佈、10 次取放結果表。
- 更新 README、`progress.md`、`troubleshooting.md`，push。
- 使用者錄一段 GUI 影片（和之前一樣的方式）。

## 5. 風險與對策

| 風險 | 對策 |
|---|---|
| YOLO 在新的相機角度偵測不穩 | 先調相機角度；不行的話，用現有的自動標註流程（Gazebo `boundingbox_camera`）補這個角度的資料再微調 |
| 定位誤差太大 | 依類別用物體中間高度求交點；必要時用偵測框底部中心修正 |
| 圓柱物體夾取時滑動或滾走 | 高摩擦、適當夾緊量、放置時慢速下降；記錄失敗原因再調整 |
| 手臂撞到另一個物體 | 兩個物體都加入 MoveIt 碰撞場景 |
| GPU 記憶體不足（Gazebo + YOLO + Ollama 同時跑，8 GB） | Gazebo 無畫面渲染約 1 GB、YOLO 約 0.3 GB、Llama 3.1 8B 約 5 GB，應該放得下；不行就改用較小的模型或讓 Ollama 用 CPU |
| Agent 編造結果、混用簡體字 | 沿用階段 1 已驗證的提示詞與程式層檢查 |
